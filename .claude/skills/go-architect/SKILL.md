# Go Architect

Keep evolving implementation in internal packages. Use cmd for wiring. Avoid giant utility packages and dependency cycles. Prefer small domain types, explicit fixed-width arithmetic, contextual errors, deterministic behavior, unit tests, fuzz tests, and benchmarks where justified.

- `../_shared/EVIDENCE_STANDARD.md`
- `../_shared/ADDRESS_SPACES.md`
